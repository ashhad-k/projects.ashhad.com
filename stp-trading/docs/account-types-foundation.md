# Account types — URL map and templates

## Routes

| URL | Template |
|-----|----------|
| `/account-types/` | `account-types/index.html` (hand-maintained) |
| `/account-types/standard/` | `account-types/standard/index.html` |
| `/account-types/zero/` | `account-types/zero/index.html` |
| `/account-types/islamic/` | `account-types/islamic/index.html` |
| `/account-types/zero-prime/` | `account-types/zero-prime/index.html` |

## Utilities (two partials — intentional)

| File | Used on |
|------|---------|
| **`/partials/header-utility.html`** | Inner pages generated by **`scripts/generate-pages.mjs`**, FAQ, etc.: **`.stp-utility-bar`** + **`stp-container`**, **hidden below `md`**. Same links as marketing shell — this is the long-standing compact bar. |
| **`/partials/stp-shell-utility.html`** | **Source of truth** for the account-types utility strip. **`account-types/*/index.html`** inlines this markup (no `fetch`). After edits, run **`node scripts/sync-account-partials.mjs`**. |

Primary nav stays **`partials/account-marketing-navbar.html`** (synced into the same pages).

**Preview:** Account-type HTML files contain **inlined** chrome, so **utility, nav, and footer render over `file://` and HTTP**. Other routes that still use **`data-include`** need HTTP (see **`/js/includes.js`**, which also resolves `/partials/...` relative to the page as a fallback).

## Footer

Canonical **`partials/footer.html`**. It is **synced into** all **`account-types/*/index.html`** files by **`scripts/sync-account-partials.mjs`**. Edit the partial, then run:

`node scripts/sync-account-partials.mjs`

Generators (e.g. **`generate-pages.mjs`**) still reference **`data-include`** + **`partials/footer.html`**.

## Scripts

Account-type routes: **`bootstrap`** → **`/js/site.js`** only (chrome is inlined).

Other pages with **`data-include`**: **`bootstrap`** → **`/js/includes.js`** → **`/js/site.js`**.
